# 待办池产品化路线图（cichuan-pool）

> **生成**：2026-10-28 · **状态**：已聊透待执行 · **真相源**：本文档是产品化全部决策的唯一登记处
> 讨论背景：从「done_pending_merge 积压 164 条」的归档准入问题出发，逐题聊透产品定位与开源化路径。
> 本文档只登记结论与理由，不重复讨论过程。

## 0. 定位一句话

**Agent-first 的任务池**：面向跑 AI 编码舰队（多 agent 无人值守开发）的独立开发者与小团队，
任务「入池 → agent 认领 → commit → 机械证据自动销账」全链路治理。
护城河 = 真实事故驱动的机制密度 + 「证据归档」这条无竞品的轴 + agent-first 数据面。

目标用户不是「要任务管理的人」（Linear/Jira 已服务），而是「被 AI 干完活没人销账、
任务账本与代码仓脱节困扰的人」。用户的踩坑史 = 本产品需求文档。

## 1. 十二项决策记录

### D1 最小闭环（Day 1 → Day 7）

- **默认体验 = 五命令三概念零配置**：`pool init` / `pool add` / `pool next` / `pool done` / `pool sync`；
  概念 = 入池、认领、销账。心理模型一句话：「我放活，agent 领走干，干完自动销账」。
- `next` 出队**必须可解释**（一行理由「为什么是这件」）+ 支持声明式过滤（`--tag`/`--lane`）；
  选件规则文档化一页，进阶可换排序键，**不支持自定义排序函数**。
- `sync` 是对新用户的销账语义（「跟代码仓对账」），底层复用证据归档；`doctor` 保留为进阶诊断。
- 默认只开「归档证据判据」，其余机制默认关。判据：**这机制解决的问题新用户第一周会遇到吗？**

### D2 进阶层组织：按「痛」分四路径

| 路径 | 触发痛点 | 机制 | 命令面 |
|---|---|---|---|
| 并发 | 多 agent 抢同一任务 | 认领竞速/文件面冲突/WIP 背压 | `pool claim --actor` |
| 规模 | 池 100+ 件不知先做啥 | 评分/分桶/老化通道 | `pool triage` |
| 审计 | agent 上周干了啥/哪件没真落地 | 事件流/交付证据/doctor | `pool doctor` |
| 治理 | 团队规矩（修复带测试等） | Fix-Class/门禁挂钩 | `pool policy` |

每条路径 = 一篇文档 + 一组命令 + 预设档对应关系；文档开头直接抄真实事故史（内容资产）。
**开关机制用预设档而非散装开关**：`solo`（默认）/ `fleet` / `team` 三档；
`pool config show` 可展开看全量、可单项覆盖；所有进阶机制缺省 fail-closed = 关。

### D3 Agent 接入面（真正的分发渠道）

用户是 agent，人是管理员。三层，顺序 1 → 3 → 2：

1. **AGENTS.md 片段先行**（零开发、复制即集成）：「开工前 `pool next`；commit 带件号 `#123`；
   收尾 `pool sync`」。**commit 带件号是证据归档的命门**，也是良性数据锁定（git 历史与池绑成一本账）。
2. **MCP server** 为核心闭环稳定后的主力开发项：现有 CLI 的薄封装，不另起逻辑。
3. **CLI agent 友好化纪律**：`--json` 全局旗标、错误码语义化（agent 按码决策，不解析人话）、命令幂等。

### D4 产品形态：本地优先

- **核心包纯 CLI**（CLI + SQLite + 证据引擎），pip install 即得；
- **看板 = 可选伴侣**（`pool board` 拉 localhost，v2 React 剥离），不进最小闭环，
  但在「规模/审计」两路径是刚需；
- **V1 明确不做多机同步**：单机单池 + 本机锁；换机走 export/import。同步是托管时代的事。

### D5 证据适配器（技术核心）

- 接口一函数一返回值：`evidence(item, ctx) → {tier: strong|weak|none, delivered, reason, details}`。
- **三档语义**：strong = 件级独立事实（in-main / 内容命中率达标）；weak = 代理证据；none = 读不到。
  `delivered` 仅 strong 档有意义；`reason` 强制（归档留人话痕迹）。
- **归档规则**：strong 自动 / weak 借 run 终态或人工 / none 只走人工。
  run 状态不是件级事实，run_terminal 只服务弱证据件。
- **git 兜底适配器零配置**：登记 commit 在默认分支可达 = strong；仅特性分支 = weak；无 sha = none。
  专用适配器（novel-platform：票据+命中率）是可选增强。
- **对抗测试为准入门禁**：夹具覆盖已合并/未合并/仅分支/无 sha 四情形；
  **谎报 strong 即测试失败**（销错账=资损级）；漏报允许（只是低效）。不对称设计第一原则。
- 多落点（一件跨多仓）V1 走人工出口 + doctor 单列；`details.repo` 预留，V2 扩 `deliveries_json`。

### D6 差异轴与节奏

- 壁垒是**时间型**不是结构型 → **早开源抢品类定义权 > 闭关攒深度**。
- 开源后机制深度成为别人跟随的路线图；「agent-first 任务治理」品类词要握在自己手里。

### D7 商业模式

- **终局 = 开源核心 + 托管/团队收费；现在 = 纯开源反哺辞川**（营收破零责任在辞川，池不抢商业化保护槽）。
- 收费点等「小团队想共享池」的真实声音出现再做，不提前猜。

### D8 数据纪律（schema = 对外承诺）

- **迁移链只增不改、永远可回滚**：启动自动逐级升级 + 迁移前自动备份 SQLite；
  历史迁移有 bug 加修正迁移，不改旧的。
- **`pool export`/`import`（JSONL 全量、格式版本化）进 V1**：换机/备份/跨版本兜底/数据可带走信任底线。
- **schema 变更两步走**：加字段先可空+兼容读写再收紧；删字段先停写再停读再删列。

### D9 安全与信任边界

- **任务文本 = 会被 agent 执行的指令**：信任模型写进 README 安全节（只写入你信任的任务）；
  外部导入任务默认 `untrusted` 标记，agent 只读不执行，人确认后转正；
  危险模式静态扫描为可选进阶提示（非防线）。
- `pool board` / MCP server **默认只绑 127.0.0.1**，`--host` 显式暴露须警告。
- **永不写用户仓**：证据探测只读 git；config 仓路径做存在性+身份校验。
- 发布走 CI + 受保护 PyPI token；依赖锁定 + pip-audit 定期审计。

### D10 许可：核心 Apache-2.0

- vs MIT：多专利授权与商标保护（此方向大厂布局密集，有实际意义）；
- vs AGPL：传播优先于防白嫖，防大厂抄托管的防御是机制深度与品牌。
- 未来团队/托管组件许可另议，不影响核心。

### D11 发布节奏与冷启动

- **发布线 = 最小闭环可跑 + 好 README，不追求完善**：
  五命令干净环境 30 分钟跑通 + git 兜底零配置归档 + 英文 README + AGENTS.md 片段 + Apache-2.0 + 基础 CI。
  进阶路径（MCP/看板打磨/预设档）发布后迭代。
- **窗口 2-4 周（业余时间）**，不拖——AI 工具圈热点轮动快。
- **冷启动三件套**：叙事文（中英，讲 164 条积压等真实事故）+ 90 秒闭环演示（README 顶部）
  + HN/V2EX/即刻同步，主打「agent-first 任务池」品类词。
- **度量三数**：周活跃安装（下载量代理）、首次归档耗时、7 日留存。初期靠社区信号，不做遥测。

### D12 分发与命名

- **pip 包 `cichuan-pool` / 命令 `pool`**；尽早占位：PyPI 名、GitHub 仓、域名（可选）。
- **独立仓**：优先 `git filter-repo` 带历史（机制演化史=资产），剥离超两天则干净起步+老仓存档链接。
- V1 只走 PyPI；CI 做「干净容器 pip install → 跑通脚本」真实冒烟；语义化版本，预 1.0 minor 可破。
- **英文文档为主**，中文留 `docs/zh/`。

### D13 社区治理与辞川边界（补充）
- 社区最小配置：CONTRIBUTING 一页 / issue 模板×2 / 公开 roadmap（=进阶四路径）/ Discussions。
  **每周固定时段处理外部 issue**，不侵蚀辞川开发时间。
- 剥离切断三类依赖：主仓规约与 hub import（novel-platform 适配器改可选 extras）、
  环境变量（`CICHUAN_RUNS_DIR` 兼容保留，新默认 `~/.cichuan-pool/`）、文档引用（改摘要+链接）。
  辞川侧以 pip/git 依赖消费，两边独立发版。

### D14 存量池迁移策略（2026-10-28 补）

- **冻结存量、干净起步**：开源新仓从零定型公开 schema（只保留通用字段；
  `launch_tier`/`claim_policy` 等内部机制字段不进公开 schema），28 版迁移链不带过去。
- 辞川内部继续用现有池，产品化版本稳定后再评估内部迁移。
- 理由：V1 schema 设计自由度最大，避免第一天把内部字段冻结成公开契约（与 D1 默认关进阶自洽）。

### D15 现存积压的过渡补丁（2026-10-28 补）

- 产品化证据引擎落地前，**先给现有池打 reconcile 分层补丁**：
  `doctor --reconcile` 准入从「run 终态 ∧ landed」放宽为「strong 件级证据（in-main ∧ strong）
  即归档，run 状态无关；弱证据件维持 run_terminal 或人工」。
- 性质 = D5 原则的预演 + git 兜底适配器的真实判据数据来源；同时清掉 164 条积压。
- 落地为容器件 #10834 下第一个子件。

### D16 发布检查项（2026-10-28 补）

- **命令名冲突检查**：`pool` 与常见工具 PATH 撞车概率需发布前验证；备选 `cipool`/`taskpool`。
- **叙事文视角**：以「池子」为主角（读者买的是「我也能用」的工具），
  辞川仅作案例出现一次，笔墨全在 agent 任务治理的通用问题与解法。

### D17 独立仓决策细则（2026-10-28 补）

- **必须新建独立仓**，三种替代均否决：现有仓直接开源（内部拓扑/事故史/私有路径随历史整体曝光，
  几千 commit 无法证明可公开审计）；fork/branch（历史原样带走，同病）；主仓 monorepo 子目录
  （主仓私有+重门禁，外部无法 PR/CI，等于没开源）。
- **两个受众两套承诺**：内部仓跟舰队节奏演进，开源仓对陌生人负稳定契约（破坏性变更走 deprecation），
  同仓必互相绑架；依赖方向单向 = 开源核心 ← 内部仓（pip/git 依赖消费）。
- **先私有后公开**：GitHub 先建私有仓做剥离打磨，达 D11 发布线再转 public，不暴露半成品。
- **历史审计前置**：filter-repo 只抽通用模块（CLI/域模型/证据）历史，抽前审计是否混入内部路径/
  敏感信息；审计不过或超两天 → 干净起步 + 老仓存档链接，演化史靠叙事文不靠 git 历史。
- **防双仓漂移纪律**：剥离完成到内部仓切换依赖消费之间，通用模块新功能只进开源仓，
  内部仓通用模块冻结功能性改动（仅修阻塞 bug），切换窗口尽量缩短。
- **账号**：个人账号或 cichuan 组织均可，transfer 保留 star/issue，品牌决策后置不挡开工。

## 2. 非目标红线（明确不做）

1. **不做第三方插件加载机制**。适配器 = 仓内模块边界 + 静态注册表。
   触发重议条件：出现第一个仓外实现方；届时也只到「config 指路径 + importlib 单模块」级别。
2. **V1 不做多机同步 / 多人协作 / 托管服务**。
3. **不做用户自定义排序函数、不做散装机制开关**（只预设档+单项覆盖）。
4. **不因跨仓件难判就退回 run 代理判据**——跨仓件恰恰是最需要件级证据的族群。

## 3. 实施路线（四阶段）

### 阶段 A：剥离开源 V1（2-4 周，发布线见 D11）

- [ ] 独立仓 + 命名占位（PyPI/GitHub，先私有仓；通用模块历史审计 → 带历史或干净起步，见 D17）
- [ ] 核心五命令收敛（init/add/next/done/sync）+ next 可解释 + sync 人话输出
- [ ] 证据适配器接口 + git 兜底 + 对抗测试夹具
- [ ] export/import JSONL
- [ ] 安全基线（untrusted 导入、localhost 绑定、只读用户仓）
- [ ] 英文 README + AGENTS.md 片段 + Apache-2.0 + CI 冒烟
- [ ] 叙事文 + 90 秒演示 + 三渠道发布

### 阶段 B：进阶路径打磨（发布后按痛点驱动）

- [ ] 预设档 solo/fleet/team + config show 展开
- [ ] 四路径文档（并发/规模/审计/治理，各含真实事故开篇）
- [ ] 看板 `pool board` 可选启动打磨
- [ ] doctor 诊断分层报告（strong/weak/none 分族 + 多落点单列）

### 阶段 C：MCP server

- [ ] CLI 薄封装为 MCP 工具集（pool_next/pool_add/pool_done/pool_sync）
- [ ] 只读/写接口权限分离

### 阶段 D：远景（等真实需求信号）

- [ ] 多落点 `deliveries_json`（跨仓件一等公民）
- [ ] 团队共享池 / 托管版（收费点，另立许可决策）
- [ ] 外部贡献的适配器生态（触发插件机制重议）

## 4. 度量与复盘

- 三数：周活跃安装 / 首次归档耗时 / 7 日留存（D11）。
- 发布后每月对照本路线图复盘一次；决策变更走修订记录，不静默改历史。
